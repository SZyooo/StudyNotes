# Linux的文件权限与目录配置

## 一、用户与用户组

文件权限有三个层级：

- 拥有者
- 用户组
- 其他人

除了普通用户外，还有一个超级用户“root”。

### 1.1 记录文件

> 通过 `man passwd`等来查看相关文件内容格式

- `/etc/passwd`：所有账户与一般身份用户信息
- `/etc/shadow`：记录账户的密码
- `/etc/group`：记录所有用户组

## 二、文件权限

### 2.1 文件属性

我们通过命令`ls -al`可以来查看所有文件的详细信息。

打印的信息主要分为7栏：

    1.文件类型与权限
    2.链接数：多少文件名关联到这个iNode
    3.拥有者账号
    4.所属用户组
    5.文件的容量大小
    6.文件的创建日期或最近的修改日期
    7.文件名字

> **文件名和iNode** ：iNode是内核数据结构，记录了文件的磁盘位置、大小等信息；目录中的文件名是iNode的一种引用。有可能多个文件名引用了同一个iNode。


我们现在主要关注打印信息的第一个字段。大致模式有点类似`dr-xr-x---`。

这个字符串主要包含了4类信息：

- 路径类型：第一个字符表示的是这是一个目录、文件还是链接文件：
  - `d` : 目录
  - `-` : 文件
  - `|` : 链接文件
  - `b` : 可按块读写的周边设备
  - `c` : 串行端口设备
- 文件拥有者权限：接下来3个字符代表的是文件拥有者的权限。其中：
  - `r` : 表示可读
  - `w` : 可写
  - `x` : 可执行
- 文件所属组用户的权限
- 其他人的权限

### 2.3 修改文件属性和权限

修改文件权限、所属组等主要使用下面三个命令：

- `chgrp` : 修改文件所属用户组
- `chown` : 修改文件拥有者
- `chmod` : 修改文件的权限
  
> 关于这些命令的详细信息查看man或者info

#### 2.3.1 `chgrp`

修改指定文件/目录所属的用户组

#### 2.3.2 `chown`

修改指定文件/目录所属的用户

同时这个命令也可以修改文件/目录所属的用户组。

#### 2.3.3 `chmod`

修改指定文件的权限。这个命令可以通过两种方式来修改文件权限：

**数字类型**

Linux下一个文件的权限一共有三种，分别基于了对应位：

- r : 100(4)
- w : 010(2)
- x : 001(1)
  
我们加法运算将权限值累加来计算一个文件的所有权限。例如对于`r-x`，权限值为4+0+1=5.

我们需要分别设置拥有者、组和其他人的权限，因此需要给定3个数字。例如对于`rwxrwx---`，结果是“770”。

**符号类型**

如果不想使用数字的话，可以使用符号：
|命令|设置目标|设置动作|权限字符|
|:-|:-|:-|:-|
|`chmod`|u</br>g</br>o</br>a|+(添加)</br>-(移除)</br>=(设置)|r</br>w</br>x|

### 2.4 目录和文件的权限区别

我们可以用rwx同时设置目录和文件的权限。对于目录和文件来说，这三种权限有什么区别呢？

**对于文件来说，所有权限都是针对文件内容**

- r: 可以读取文件的内容
- w: 可以修改文件的内容（注意不是删除文件！）
- x: 可以执行该文件
  
**对于目录来说，所有权限都是针对文件列表**

- r: 可以查看指定目录的文件名列表（但是不能查看详细信息，必须搭配x才能查看每个文件的详细信息）
- w: 可以修改指定目录的文件列表，例如添加/删除文件（必须搭配x，否则无效）
- x: 可以进入该目录，将该目录设置为当前工作目录
  
### 2.5 Linux文件种类和扩展名

#### 2.5.1 文件种类

- **常规文件**

  常规文件包括：
   - 纯文本文件
   - 二进制文件
   - 数据文件
  在`ls`命令结果里面前缀符号是`-`
- **目录**
  在`ls`命令的结果里面前缀是`d`
- **链接文件**
  在`ls`命令的结果里面前缀是`l`
- **设备与设备文件**
  主要包括：
  - 区块设备文件：磁盘、硬盘等。`ls`的结果中前缀为`b`
  - 字符(串行)设备文件：键盘、鼠标等。`ls`的结果中前缀为`c`
- **套接字文件**
  `ls`命令的结果中前缀是`s`

- **管道文件**
  pipe。`ls`命令的结果中前缀是`p`

#### 2.5.2 文件扩展名

要明确的是：**linux下，一个文件是否可以执行与它的后缀无关**。这个和Windows是不一样的，windows中文件后缀名如果是`.bat`/`.exe`/`.com`的话，则该文件被认为是可以执行的。

Linux下，只要一个文件具有`x`权限，就可以被执行。但是具体是否能否成功执行还得取决于文件类型。对于`txt`文件而言，添加`x`权限之后虽然可以执行，但是显然没法执行成功。

不过，我们仍然可以借助文件后缀来区分文件类型。常见的文件后缀及其含义有：

- `.sh` : Shell脚本
- `*Z` `.tar` `.tar.gz` `.zip` `.tgz` : 压缩文件
- `*.html` `.php` :网页相关文件
  
#### 2.5.3 文件名长度限制

Linux下一个文件的名字最长为255字节。

## 三、Linux目录配置

每个Linux发行版的目录结构都高度相似，这是因为它们都遵循一个标准。

### 3.1 Linux目录配置的依据：FHS

FHS(Filesystem Hierarchy Standard)标准的作用是规范指定目录下应该放置什么类型的数据。

总体来说，FHS将目录按照1、是否可分享2、是否频繁改动两个维度进行划分。例如：

||可分享（shareable）|不可分享（unshareable）|
|:-|:-|:-|
|**不变（static）**|/usr(软件存放处)</br>/opt(第三方辅助软件)|/etc(配置文件)</br>/boot(启动与内核文件)|
|**可变动(variable)**|/var/mail(用户邮箱)</br>/var/spool/news(新闻组)|/var/run(程序相关)</br>/var/lock(程序相关)|

- **可分享** ： 可以分享给其他系统进行挂载的目录。
- **不可分享**：本机相关的目录，例如存放套接字文件等的目录，仅与本机系统相关，因此不可分享
- **不变** ：配置文件、函数库、说明文件等
- **可变动** ：经常修改的数据，例如日志文件等

事实上，FHS仅仅针对下面三层目录给出了文件存放建议：

- `/` ：根目录
- `usr`(Unix Software Resource) ：与软件安装/执行有关
- `var`(Variable) ：与系统运行过程有关

#### 3.1.1 `/` root目录

根据FHS标准建议：**根目录`/`所在分区应该越小越好，且应用程序安装的软件最好不要与根目录放在同一个分区内，保持根目录越小越好**。

下面列出FHS建议`/`目录下面必须存在的目录（即使没有实际目录，也建议有一个同名的目录链接）。

|目录|应放置的文件内容|
|:-|:-|
|`/bin`|主要放置各种命令，这些命令在单人维护模式下仍然可以使用|
|`/boot`|主要存放启动时候需要的文件，包括Linux内核文件以及启动选项和启动所需配置等|
|`/dev`|Linux上任何设备和接口设备都是以文件的形式存在于这个目录当中|
|`/etc`|系统主要的配置文件都放在这个路径下，例如账户密码账号。FHS建议这个路径**不要放置可执行文件**|
|`/lib`|系统的函数库。FHS要求这个路径下必须存在子目录`/lib/modules/`，放置可抽换式的内核相关模块（驱动程序）|
|`/media`|放置的是可删除的设备，例如DVD、软盘等|
|`/mnt`|用来放置临时挂载的设备|
|`/opt`|放置第三方辅助软件。例如KDE桌面管理系统，作为独立软件，建议放置在这个路径|
|`/run`|早期的FHS规定系统启动后产生的各项信息放置在`/var/run`目录下；后面FHS规范到了`/run`下面|
|`/sbin`|放置在这个路径下的是启动过程所需要的命令，包括启动、修复、还原系统。例如fdisk, fsck等|
|`/srv`|可以看作是service的缩写。是一些网络服务启动之后放置数据的目录|
|`/tmp`|让一般用户或者程序暂时放置文件的地方。这个目录是每个人都可以存取的，建议定期清理。FHS建议每次启动系统都清理一下这个路径|
|`/usr`|下面介绍|
|`/var`|下面介绍|

除了上面的必须存在的目录，FHS建议同时存放下面的目录：
|目录|应放置的文件内容|
|:-|:-|
|`/home`|系统默认的用户家目录。此外，</br>`~`:代表当前用户的家目录</br>`~ysz`:表示用户ysz的家目录|
|`/lib<qual>`|用来存放与`/lib`不同格式的二进制函数库，例如`lib64`函数库等|
|`/root`|系统管理员root的家目录。建议将root的家目录和根目录放置在同一个分区|

除了上面FHS规定的目录之外，我们还应该了解一下下面这三个目录：

|目录|应放置的文件内容|
|:-|:-|
|`lost+found`|这个目录是使用标准的ext2、ext3、ext4文件系统格式才会产生的目录，目的是当文件系统发生错误时，将一些遗失的片段放置在这个目录下面。如果是用的是xfs文件系统，则不会存在这个目录|
|`/proc`|这个目录本身是一个虚拟文件系统，放置的数据都在内存中，例如系统内核、进程信息、外接设备的状态以及网络状态等|
|`/sys`|和`/proc`类似也是一个虚拟文件系统，主要也是记录内核与系统硬件先骨干的内容|

#### 3.1.2 `/usr`目录

很多用户会错以为`/usr`目录的含义是user的缩写，起始它的含义是Unix Software Resource的缩写，代表是的Unix操作系统的软件资源。

`/usr`目录存放的数据被设计为可分享+不可改变（shareable，static）的，意味着可以通过网络挂载到其他主机上。

所有随着发行版一同发行的软件都会放置在这个目录下面。

FHS要求下面这些子目录是必须存在的：

|目录|应放置文件的内容|
|:-|:-|
|`/usr/bin/`|放置所有一般用户都能使用的命令。另外，FHS要求这个目录下面不能存在子目录|
|`/usr/lib/`|与`/lib`功能类似|
|`/usr/local/`|系统管理员在本机安装自己下载的软件（非发行版默认提供），建议安装在这个目录|
|`/usr/sbin/`|非系统正常运行所需要的系统命令|
|`/usr/share/`|放置只读的数据文件，一般都是部分硬件架构都可以读取的文件，因此一般都是文本文件，例如`/usr/share/man/`|

FHS建议存在下面这些目录：

|目录|应放置文件的内容|
|:-|:-|
|`/usr/games/`|与游戏比较相关的数据放置处|
|`/usr/include/`|c/c++等程序文件的头文件与包含文件放置处|
|`/usr/libexec/`|某些不被一般用户常用的执行文件或者脚本放置处|
|`/usr/lib<qual>`|与`lib<qual>`相同|
|`/usr/src/`|一般源代码建议放置在这里|

#### 3.1.3 `/var`目录

这个目录是在系统运行之后才会渐渐占用硬盘的目录。这个目录下面存放的主要是经常性变动的文件，包括缓存、日志文件以及软件运行所产生的文件等。

FHS要求的子目录有：

|目录|应放置文件内容|
|:-|:-|
|`/var/cache/`|应用程序本身运行过程中产生的一些缓存|
|`/var/lib/`|程序本身执行的过程中需要的数据文件放置的目录。此目录下面各自的软件应该有各自的目录|
|`/var/lock/`|主要存放加锁文件|
|`/var/log/`|日志文件放置的目录|
|`var/mail/`|放置个人邮箱的目录|
|`var/run/`|某些程序或者服务启动之后，会将它们的PID放置在这个目录|
|`var/spool/`|放置队列数据，被取出之后就会被删除。例如没有接收的邮件、等待发出的邮件等|
