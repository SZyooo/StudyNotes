# Hello, world of concurrency in C++

## 一、概念

### 1.1 task switching

通过不停的在不同任务之间切换执行，达到一种并发的效果。

task switching需要进行上下文切换：

**context switching**: 

- 保存CPU状态和当前指令计数器
- 决定选择切换的task
- 加载目标task的CPU状态
- 加载目标task的指令、数据的内存

### 1.2 多处理器和多核处理器

- multiple processors: 多处理器
- multiple cores withing a processor: 多核单处理器

**hardware concurrency**: 无论是上面哪种情况，我们都说机器具有hardware concurrency。

### 1.3 实现并发的途径

#### 1.3.1 多进程

通过执行多个进程来实现并发，进程之间通过操作系统提供的方式（信号、管道、文件等）进行进程间通信。

**优点**：

- 安全性：不同进程之间的内存地址是独立的，这是OS提供的一层保护机制
- 简易性：高级的进程间通信的方法能够更容易写出健全的并发代码
- 多机器：可以通过网络来实现多机器之间的并发

**缺点**：

- 进程间通信的方法效率比较低，会损耗性能
- 进程的消耗非常大。操作系统需要一定的时间来启动一个进程同时需要内部资源来维护一个进程

#### 1.3.2 多线程

通过执行多个线程来实现并发。多线程方式下，不同线程之间共享地址空间，极大地简化了线程间通信的消耗。

**优点**:

- 性能高。无论是维护一个线程还是线程之间的通信都需要极小的overhead

**缺点**:

- 难开发：共享地址空间使得开发过程中必须小心谨慎，保证共享数据在多线程同时访问下的一致性

## 二、使用多线程的优势

### 2.1 关注点分离

我们将不同功能模块的代码放入不同的线程，例如将UI响应以及数据处理的代码分离，这样可以尽量避免两个功能模块之间逻辑的交织，写相应代码的时候也就能更多地关注一个功能。

### 2.2 更高的性能

很直观的，使用多线程可以提高程序性能。有两种方法来通过多线程来提升程序性能：

- **task parallelism**：将一个Task切割成小份，用多线程并行执行
- **data parallelism**：提升任务规模。用并发执行更大规模的任务

## 三、什么时候不要使用多线程

**当使用多线程的代价大于收益的时候，就不要使用多线程**。

使用多线程的代价主要有：

- 代码的复杂度提升。提升编写代码的心智复杂度以及增加后期维护的难度
- 性能损耗并不能忽略。每个线程都需要内核分配资源以及在同一个地址空间分配独立的栈空间，这些性能损耗并不能忽略
- 线程也是一个有限的资源。大量线程会迅速吃掉OS的资源，消耗内存空间
- context switching不能忽略。线程之间的调度显然需要进行context switching，太多的线程会导致context switching次数急剧上升，导致更多的性能消耗。
