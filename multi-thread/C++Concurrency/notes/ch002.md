# 管理线程

## 一、基本的线程管理

**基本模型**：每个C++程序至少有一个线程，由C++ runtime启动，执行`main`函数。可以在`main`函数启动其他线程

### 1.1 启动线程

**通过构造`std::thread`对象来启动一个线程**

- 函数启动
```C++
void do_some_work();
std::thread t(do_some_work);
```

- 可调用对象启动
```C++
class task{
    public:
        void operator()()const{
            //...
        }
};
task tsk;
std::thread t(tsk);
```
> **[!NOTE]** tsk对象会被拷贝到线程的内存中。

- lambda表达式

```C++
std::thread t([]{ /*...*/ });
```

### 1.2 等待线程结束

`std::thread`对象在析构的时候，如果仍然关联着线程对象，会调用`terminate`函数终止程序。

> **[NOTE]** 注意是析构的时候，并不是线程结束的时候。因此我们在启动线程之后到它被析构（不是到线程执行完毕）之前任意时候我们可以调用`join`或者`detach`来打断关联

- **通过调用`join`来等待线程执行结束**

**`join`只能执行一次**。`join`函数会清理线程资源，包括切断`std::thread`对象和实际线程之间的关联。

- **通过调用`detach`来直接断开连接**

`detach`直接将`std::thread`对象和线程之间的联系打断，不会等待它执行结束。

> 无论是`join`还是`detach`都要求`std::thread`对象关联到了线程。因此一旦通过`join`或者`detach`打断了这种关联，就不能在调用两个中的任何一个
> **可以将线程看作是`std::thread`对象管理的资源**

## 二、传递参数

给线程函数传递参数的语法很简单：

```C++
void f(int a, int& b);
int x = 4;
std::thread t(f, 3, x); //虽然f第二个参数接受引用，也是将x拷贝到线程栈，然后将新对象的引用传递给函数
```

**线程传递参数永远是将参数拷贝到线程内存**。因此，即使函数参数签名是一个引用，执行的结果也是将实参拷贝到线程栈然后将新对象的引用传递给函数。

> **[WARNING]** 这种参数拷贝可能会导致一些不经意的问题：
> ```C++
> void f(std::string s){/*...*/}
> void oops(){
>   char buffer[1000];
>   //... init buffer
>   std::thread t(f, buffer);
>   t.detach();
> }
> ```
> 上面的代码中，将buffer指针拷贝到线程栈中之后，`oops`函数就退出了，但是线程背后还在用`buffer`指针构造`std::string`对象。这是因为**线程参数拷贝是先将参数拷贝，然后在线程栈中进行类型转换**。解决办法很简单:
>```C++ 
> void oops(){
>   char buffer[1000];
>   //... init buffer
>   std::thread t(f, std::string(buffer)); //将std::string的构造放在oops函数内部完成
>   t.detach();
> }
>```
