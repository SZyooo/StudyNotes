# `shared_ptr`

## 一、基本结构

`shared_ptr`内部的结构分为两个：一个是引用计数块一个是资源块。如果给定了deleter的话则外加一个deleter。

## 二、强引用计数和弱引用计数

`shared_ptr`内部会存在两个引用计数：强引用计数和弱引用计数。

- **两个引用计数的增减都是原子的**
- **强引用计数会导致资源被析构（<font color="red">不一定被释放</font>）**
- **弱引用计数归0会导致引用计数块被直接delete（弱引用归0则强引用也一定归0，因此资源一定会被释放）**

## 三、`std::make_shared`

使用这个结构创建智能指针中，引用计数块和资源块被放在连续内存：

```c
class RefCounter
{
    Resource res;
    int usr;
    int weak;
};
```

而使用其他方法创建的智能指针，引用计数块和资源块是分离的：

```c
class RefCounter
{
    Resource* res;  //注意这里用的是指针
    int usr;
    int weak;
};
```

## 四、`weak_ptr`

`weak_ptr`总是伴随着`shared_ptr`，它的作用是增加`shared_ptr`的弱引用。它能够阻止`shared_ptr`自身的释放，但是无法阻止资源的**析构**。

注意我这里用的词是**“析构”**，而不是“释放”。原因是这样的：

我们前面说过：使用`std::make_shared`构造出来的智能指针，资源和引用计数块是连续内存的。这意味着，<font color="red">智能指针自身如果不被释放的话，资源的内存也不会被释放</font>。这个时候，如果强引用计数归0，但是弱引用计数不为0的话，会导致虽然调用资源的析构函数，但是指针自身没有被释放，则资源占据的那块内存仍然存在。
