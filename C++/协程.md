# C++20协程

C++20引入的协程是一种无栈协程。

<details>
<summary>无栈 vs. 有栈</summary>
经典的有栈协程做法是为每一个协程保留一个固定大小的调用栈。而C++采用的协议栈则不会为每一个协程分配调用栈，而是将协程状态、局部变量等打包为一个对象分在堆上。
</details>

如果一个函数内部出现了下面三个关键字之一，就是一个协程：

- `co_await`：暂停执行直到恢复
- `co_yield`：暂停执行并且返回一个值
- `co_return`：完成执行并且返回一个值
  
## 一、限制

协程具有以下限制：

- 不能使用可变参数
- 不能使用普通的`return`语句
- `consteval`函数、`constexpr`函数、构造函数、析构函数和main函数不允许是协程

## 二、3个关键对象

每个协程都关联到下面三个重要的对象：

### 2.1 promise对象

这个对象主要在协程内部操作，可以认为是对协程外部的一种“承诺”。协程通过这个对象来提交结果或者异常。例如，调用者通过`co_yield`返回值的时候，返回值是promise对象的`yield_value()`函数返回值。

<span id="coroutine_handle"></span>
### 2.2 协程句柄（handle）

这个对象是协程外部管理协程的一个句柄，用来恢复协程的执行或者销毁协程帧。

协程句柄非常类似一个C的指针，可以被随意拷贝。为了避免内存泄露，我们应该调用它的`destroy`来释放底层的协程状态。如果一个句柄手动销毁了底层的协程状态，其他指向同一个协程状态的句柄将指向无效内存。

C++设计了三种类型的协程句柄：
```c++
template<PromiseType = void>
struct coroutine_handle;

//特化1
template<> struct coroutine_handle<void>;

//特化2
template<> struct coroutine_handle<std::noop_coroutine_promise>;
using noop_coroutine_handle = std::coroutine_handle<std::noop_coroutine_promise>;
```

其中，`void`版本可以理解为“空指针”；`noop_coroutine_handle`则是可以理解为一个支持`resume`、`done`等操作的空指针：如果我们在没有实际引用协程状态的`coroutine_handle`上执行这些函数，则会出现异常，但是在`noop_coroutine_handle`上执行则没有问题。换句话说，`noop_coroutine_handle`有点像一个哨兵。

在拿到了promise对象的情况下，我们可以通过`std::coroutine_handle<Promise>::from_promise(promise)`来获取协程状态的handle。


### 2.3 协程状态

这个是一个编译器生成的内部对象，主要用来管理协程。这个对象内部包含以下内容：

- promise对象
- 参数（全部按值复制）
- 暂停点的一些表示，以便知道如何恢复以及局部变量管理
- 局部变量和临时变量
  
## 三、协程执行

协程开始执行之后，主要会执行以下操作：

1. 使用`operator new`来分配协程状态对象
2. 将协程函数的所有参数都复制到协程状态对象中：按值参数将移动或者复制，**引用参数仍然是引用**
3. 调用promise对象的构造函数。如果promise类型有一个接收所有协程参数的构造函数，则用复制后的协程参数调用该构造函数，否则调用默认构造函数
   > 这里有一个小细节：在协程状态对象构造好了之后创建promise对象。意味着我们可以在promise对象的构造函数里面就直接通过`std::coroutine_handle<Promise>::from_promise`来获取有效的协程对象的handle。
4. 调用`promise.get_return_object()`并且将结果保存在局部变量中。协程首次暂停的时候，将调用的结果返回调用者。**这一步之前或者这一步出现了异常，都会直接传播给调用者，而不是放入到promise对象中**。
5. 调用`promise.initial_suspend()`，该函数需要返回一个awaiter对象，然后`co_await`该对象。
6. 在`co_await promise.initial_suspend()`恢复时，开始执行协程的主体。

协程内部对于外部对象的引用需要特别关心，下面举出两个例子来对比：

```c++
void bad(){
    coroutine h = [i=0]()-> coroutine
    {
        std::cout << i;
        co_return;
    }();
}

void good(){
    coroutine h = [](int i)->coroutine
    {
        std::cout << i;
        co_return;
    }(0);
}
```

例子中，两个协程调用都是使用lambda，但是第一个lambda中的i是捕获对象，意味着那个`i`是lambda匿名对象的成员，而协程函数内部输出的`i`是对匿名对象的`i`的引用。可是立即调用完了lambda之后，临时的lambda对象就被析构了，这样的话协程内部引用的`i`就过期了。
而第二种方法则是通过参数的方法将`i`传递给协程函数，这样的话即使临时lambda对象析构，协程内部的`i`也是有效的。

## 四、协程暂停

当协程到达暂停点的时候，会执行下面的操作：

1. 之前获得的返回对象会返回给调用者；如果需要还会隐式转换为协程的返回类型
2. 如果协程执行到`co_return`，它会执行如下操作：
    a. 对于以下情况，调用`promise.return_void()`:
        - `co_return;`
        - `co_return expr;` 如果`expr`类型是`void`
    b. 如果`co_return expr`中的`expr`不是`void`，则会调用`promise.return_value(expr)`
    c. 接着以相反的创建顺序销毁自动存储的变量
    d. 调用`promise.final_suspend()`并且`co_await`其结果

如果协程执行到末尾没有遇见任何`co_return`，则等同于`co_return;`。如果这个时候promise对象没有定义`return_void`，则行为未定义。
   
## 五、协程异常

如果协程内部出现未捕获异常，则会执行如下操作：

1. 捕获异常并且在`catch`块中调用`promise.unhandled_exception()`
2. 调用`promise.final_suspend()`并且`co_await`其结果。**在这一步企图恢复协程是未定义行为**
3. 调用promise对象的析构函数
4. 调用函数参数副本的析构函数
5. 调用`operator delete`析构协程状态
6. 将执行权返回给调用者
   
## 六、动态分配

协程状态是通过非数组的`operator new`动态分配的。

我们可以给Promise类型[重载`operator new`](定义new和delete.md)，则分配协程状态内存则会使用这个重载`operator new`。

如果我们给Promise重载的`operator new`带有除了第一个参数`size_t`还有其他参数，同时这些参数的类型和协程函数的参数类型完全匹配，则会将协程函数的参数传递给Promise的构造。

如果申请协程状态内存失败，则默认会抛出`std::bad_alloc`异常。但是，如果我们提供了`Promise::get_return_object_on_allocation_failure()`成员函数定义，则分配将使用`operator new`的nothrow形式，并且分配失败的时候协程会调用这个函数并且将返回值返回给调用者。

## 七、`Promise`

`Promise`类型是在协程返回类型上应用`std::coroutine_traits`返回的结果。

假设
- `R`和`Args...`表示协程的返回类型和参数类型列表
- `ClassT`表示如果协程被定义为非静态成员函数的时候，其所属类型
- `cv`表示协程被定义为非静态成员函数的时候，函数声明中的cv限定符
则，Promise类型由以下方式确定：

- 如果协程没有被定义为对象成员函数：</br>`std::coroutine_traits<R, Args...>::promise_type`
- 如果协程被定义不是右值引用限定的成员函数：</br>`std::coroutine_traits<R, cv ClassT&, Args...>::promise_type`
- 如果协程被定义为右值引用限定的成员函数：</br>`std::coroutine_traits<R, cv ClassT&&, Args...>::promise_type`

## 八、<font color="red">co_await </font>

`co_await`是一个运算符。对于表达式：

```c++
co_await expr;
```
它不允许出现在下面场景中：

- `catch`块中
- 声明语句，除非是声明语句的初始化器
- 在`if`、`switch`、`for`语句的变量声明部分，除非是作为变量的初始化器
- 默认参数
- 具有静态或者线程存储生命周期的块作用域变量的初始化器

> 对于最后一点：实际上全局变量的初始化器也不可能出现`co_await`，因为它必须出现在函数内部

这个运算符主要执行下面的操作：

1. 将`expr`转换为一个可等待对象（awaitable）：
    - 如果`expr`本身是由初始暂停点、最终暂停点或者`yield`表达式生成，则可等待对象是`expr`本身
    - 否则，如果当前协程的Promise类型提供了成员函数`Promise::await_transform`，则将通过调用`promise.await_transform(expr)`来进行转换
    - 否则，可等待对象是`expr`对象本身
2. 然后，获取等待器（awaiter）：
    - 如果存在下面两个`co_await`函数重载：
      - `awaitable.operator co_await()`
      - `operator co_await(static_cast<Awaitable&&>>(awaitable))`
    则调用这个重载获取awaiter
    - 否则将awaitable作为awater本身
    - 否则程序出错
3. 获取到awaiter之后，会立即调用`awaiter.await_ready()`。这个函数的作用是一种“短路”行为：如果等待条件已经满足，例如等待的变量已经就绪，则直接返回。
如果这个函数返回`false`，则协程就会被暂停，同时会构造协程状态对象（从这里可以看出来`awaiter.await_ready()`返回`true`可以避免协程状态的构造）。
接着，`awaiter.await_suspend(handle)`被调用。其中`handle`就是协程handle，引用的就是底层的协程状态。`awaiter.await_suspend`可以返回以下几种类型：
    - `void`：控制立即返回给调用者
    - `bool`:
      - `true`:将控制返回给调用者
      - `false`: 恢复协程执行
    - 其他协程的handle：被返回的handle会被恢复执行
    - 抛出异常：异常被捕获，同时恢复协程，然后立即将异常重新抛出
4. 最后，无论协程有没有被阻塞，都会调用`awaiter.await_resume()`。这个函数的返回值就是`co_await expr`的结果。
    - 如果`await_ready()`返回`true`，则立即调用`await_resume()`
    - 如果`await_ready()`返回`false`，则阻塞线程，然后调用`await_suspend`；当外界通过handle重启这个协程的时候，则会调用`await_resume()`。

awaiter对象是协程状态的一部分，它会在`co_await`表达式结束之后被销毁。但是在`awaiter.await_suspend`之前，协程就会被挂起。因此在跨线程的时候可能会出现问题。下面是[cppreference](https://cppreference.cn/w/cpp/language/coroutines)给的一个实例代码：

```c++
#include <coroutine>
#include <iostream>
#include <stdexcept>
#include <thread>
 
auto switch_to_new_thread(std::jthread& out)
{
    struct awaitable
    {
        std::jthread* p_out;
        bool await_ready() { return false; }
        void await_suspend(std::coroutine_handle<> h)
        {
            std::jthread& out = *p_out;
            if (out.joinable())
                throw std::runtime_error("Output jthread parameter not empty");
            out = std::jthread([h] { h.resume(); });
            // Potential undefined behavior: accessing potentially destroyed *this
            // std::cout << "New thread ID: " << p_out->get_id() << '\n';
            std::cout << "New thread ID: " << out.get_id() << '\n'; // this is OK
        }
        void await_resume() {}
    };
    return awaitable{&out};
}
 
struct task
{
    struct promise_type
    {
        task get_return_object() { return {}; }
        std::suspend_never initial_suspend() { return {}; }
        std::suspend_never final_suspend() noexcept { return {}; }
        void return_void() {}
        void unhandled_exception() {}
    };
};
 
task resuming_on_new_thread(std::jthread& out)
{
    std::cout << "Coroutine started on thread: " << std::this_thread::get_id() << '\n';
    co_await switch_to_new_thread(out);
    // awaiter destroyed here
    std::cout << "Coroutine resumed on thread: " << std::this_thread::get_id() << '\n';
}
 
int main()
{
    std::jthread out;
    resuming_on_new_thread(out);
}
```

上面代码中，创建的线程立即调用了`handle.resume`，如果它的调度足够快的话，则在`await_suspend`函数返回之前，协程已经结束了`co_await`语句，导致临时的`awaitable`对象被析构了，因此`await_suspend`函数里面尝试访问成员`p_out`可能就会出错。

## 九、awaitable和awaiter

前面的`co_await`表达式的作用对象需要是一个awaiter或者可以转为一个awaiter。所谓的awaitable有点像promise一样，是指支持指定三个接口的类型，而awaiter是awaitable类型的具体对象。换句话说，awaitable是指定义了指定3个接口的类，而awaiter是指这种类的具体对象。

根据`co_await`我们知道，一个awaitable需要定义下面三个接口：

```c++
struct Awaitable{
    bool await_read();
    void await_suspend(std::coroutine_handle<>); //可以是其他返回值，详细见co_await
    void await_resume();
}
```

## 十、`co_yield`

`co_yield`表达式的作用是向调用者返回一个值并且暂停当前协程。

```c++
co_yield expr;
co_yield braced-init-list;
```
它等同于：
```c++
co_await promise.yield_value(expr);
```
