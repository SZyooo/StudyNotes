# Oskar Stålberg程序化生成地形算法

作为游戏《Townscaper》开发者，Oskar Stålberg设计了一种很不错的程序化生成建筑、地形的算法。本片笔记就是来对他的算法进行解析和记录。

<image src = "./img/Snipaste_2026-01-17_15-15-09.png">

## 一、网格化

算法的第一步是对空间进行网格化，让玩家仅仅允许在网格中放置地形模块：

<image src= "./img/Snipaste_2026-01-17_15-16-05.png">

然后我们在这些网格中放置我们的地形。

不过很显然，为了让这些地形相邻网格之间的地形模块能够平滑衔接，我们需要为不同的情况考虑。穷举所有的可能情况，即使地图中只有水和土地，我们也需要设计总共256种情况（即使通过引入旋转，我们也需要绘制15种）！

<image src= "./img/Snipaste_2026-01-17_15-23-01.png">

## 二、双网格

解决上面问题的方法是使用双网格。

双网格的思路很简单：除了表面的一层网格之外，我们在它下面一层新建一个新的网格，并且让这个网格和上面的网格错开半个单位，类似这样：

<image src= "./img/Snipaste_2026-01-17_15-30-32.png">

然后，我们不将地块放置在上面网格层，而是放在下面的网格**顶点**上。要绘制顶部网格的一块，我们需要更新它中心的顶点周围的四个底部网格。这样一来，我们可以极大地简化我们需要绘制的地块——我们将需要绘制的地块从15种降低到了6种！

<image src= "./img/Snipaste_2026-01-17_15-48-48.png">

这样做还有一个好处是我们能够把四边形的凸角和内部的凹角画的更加圆润，因为我们现在绘制是围绕顶点绘制的:

<image src= "./img/Snipaste_2026-01-17_15-54-28.png">

（上图中我们绘制的是对角的两个顶点。可以看到我们有\frac{1}{4}的空间来绘制顶点，这样我们可以有更多的空间绘制更加圆润的顶点）

我们通过这种方法能够创建出平滑连接的地图了。但是因为是在方方正正的矩形网格内部的创建的，所以看上去程序化的迹象比较明显。有什么方法可以在这个方面进行优化吗？一种方法是我们将网格扭曲。

## 三、添加随机性：扭曲网格

网格扭曲的思路很简单：我们将网格的顶点稍作偏移：
<image src = "./img/Snipaste_2026-01-17_16-07-20.png">

当然，我们需要将我们的地形模块跟着进行拉伸。主要思路是这样的：

- 我们在模型上定义一组控制点，例如使用模型的AABB包围盒：
    <image src = "./img/Snipaste_2026-01-17_16-13-31.png">

- 我们将模型的每个顶点转化为基于这些控制点的百分比位置
    <image src = "./img/Snipaste_2026-01-17_16-14-44.png">

- 然后我们通过拉伸这些控制点，来拉伸模型的顶点
    <image src = "./img/Snipaste_2026-01-17_16-16-32.png">

## 六、跨越模块

为了进一步消除程序化的痕迹，我们可以设计一些跨越多个网格的模块。

设计好了跨越模块之后，我们在放置模块的时候，检查和它邻接的8个模块，查看是否满足某些匹配模式；这是一个“扩散”的过程：如果找到了匹配某个模式的邻接模块，则进一步在这个模块的邻居上进行模式匹配。然后我们将多个匹配的模块替换为跨越模块，这样一来就丰富了模块的大小，不再是提前固定的形状了。这进一步丰富了地图。
