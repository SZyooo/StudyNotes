# 多播与广播

## 一、多播

多播（Multicast）是基于UDP完成的。多播数据将传递给加入到特定组的大量主机。

### 1.1 多播数据的传输方式及流量方面的优点

- 多播服务器端针对特定多播组，只发送一次数据
- 即使只发送一次数据，但组内的所有客户端将接收数据
- 多播组数可在IP地址范围内任意增加
- 加入特定组即可接收发往该多播组的数据

一个D类IP地址（224.0.0.0~239.255.255.255）可以代表一个多播组。

多播基于UDP，多播数据包的格式与UDP数据包相同，但是多播数据包在网络上会被路由器复制传递到多个主机，因此，**多播需要借助路由器完成**。

> 虽然理论上可以完成多播通信，但是不少路由器并不支持多播；或者即使支持也会因为网络堵塞问题阻断多播

### 1.2 路由和TTL

为了传递多播数据包，必须设置TTL（Time to Live）。

**TTL** 表示的是数据包的转发次数。每经过一次路由器就会-1。当TTL衰减到0的时候就会被丢弃。

设置TTL是通过套接字属性`IPPROTO_IP/IP_MULTICAST_TTL`完成的：

```c
int send_sock;
int time_to_live=64;
//...
send_sock=socket(PF_INET, SOCK_DGRAM, 0);
setsockopt(send_sock, IPPROTO_IP, IP_MULTICAST_TTL, (void*)&time_to_live, sizeof(time_to_live));
```

### 1.3 加入多播组

加入多播组也是通过设置套接字属性完成的，设置的属性为`IPPROTO_IP/IP_ADD_MEMBERSHIP`:

```c
int recv_sock;
struct ip_mreq join_addr;
//...
recv_sock=socket(PF_INET, SOCK_DGRAM, 0);
//...
join_addr.imr_multiaddr.s_addr="多播组地址";
join_addr.imr_interface.s_addr="加入多播组的主机地址信息";
setsockopt(recv_sock, IPPROTO_IP, IP_ADD_MEMBERSHIP, (void*)&join_addr, sizeof(join_addr));
//...

```

其中关于`ip_mreq`的定义为：

```c
struct ip_mreq                      //ip_mreq: IP Multicast REQuest
{
    //imr: IP Multicast Request
    struct in_addr imr_multiaddr;       //加入的多播组IP
    struct in_addr imr_interface;       //加入到多播组的IP，可以使用INADDR_ANY将本地任意IP加入
};
```
### 1.4 `bind`和`IP_ADD_MEMBERSHIP`的区别

编写UDP多播的时候会发现，除了需要将套接字`bind`到多播IP之外，还需要通过`setsockopt`的`IPPROTO_IP/IP_ADD_MEMBERSHIP`属性加入到多播组。很容易产生这个疑问：

**既然都`bind`到了多播IP了，为什么还要设置属性？加入多播IP不能表达加入多播组吗？**

实际上，这两个接口表达是不同的含义：

- **`bind`函数是本机内部的操作**：告知操作系统这个套接字需要监听这个\<ip>+\<port>这个地址的数据

- **`IP_ADD_MEMBERSHIP`属性则是网络层面的操作**：设置了这个属性之后，操作系统会将一个IGMP（Internet Group Management Protocol）协议报文给路由器，告知自己这个网络节点加入到某个广播组

这意味着什么呢？假设本地有一个进程A请求加入了广播组`1`，那么，即使进程B不主动加入到广播组`1`，只要它的UDP套接字`bind`到了该广播组的IP，端口也跟广播信息发送的端口匹配，那么它也能接受到该组的广播数据。

### 1.5 什么时候退出多播组？

#### `IPPROTO_IP/IP_DROP_MEMBERSHIP`主动离开

设置这个属性，让主机主动发送IGMP离开报文

#### 被动离开

进程退出的时候，操作系统会回收套接字资源。如果一个套接字成功加入了某个多播组，则操作系统会在回收的时候触发`IP_DROP_MEMBERSHIP`操作

#### 引用计数

主机会对一个多播组进行引用技术。每个加入该多播组的套接字会让计数+1，主动/被动离开则会让计数-1。只有计数=0之后，主机才会向路由器发送IGMP leave报文。

#### 超时离开

路由器会定期发送IGMP查询报文，如果主机在2~3论查询中没有回复的话，则路由器会主动将本机移除广播组

### 1.6 MBone

多播技术是基于MBone（Multicast Backbone，多播主干网）实现的。这是一个通过网络协议构成的虚拟网络结构。建立MBone的协议中，IGMP协议是核心协议之一。

## 二、广播

同样是向多台机器发送数据，多播能跨越不同网络，而广播只能在同一网络内的主机发送数据。

### 2.1 广播的理解及实现方法

广播是向**同一网络**中的所有主机传输数据的方法，和多播相同，广播也是基于UDP的。根据传输数据的地址形式，广播分为两类：

- 直接广播（Directed Broadcast）
- 本地广播（Local Broadcast）

其中，直接广播给定的地址是目标网络的网络地址，例如`192.12.34.255`，这会向处于`192.12.34`网络的所有主机发送消息。**理论上这种指定目标网络的方法可以跨路由器广播到其他网络，但是路由器是默认禁用转发直接广播消息的，所以直接广播也只能指定本地网络**。如果指定其他网络，会发现发送不出去。

而本地广播给定的IP地址则固定是`255.255.255.255`，表示向主机所在的网络发送数据。

发送广播消息需要执行两个步骤：

- 设置套接字属性`SOL_SOCKET/SO_BROADCASE`：

```c
int send_sock;
int bcast = 1;
send_sock=socket(PF_INET, SOCK_DGRAM, 0);
setsockopt(send_sock, SOL_SOCKET, SO_BROADCASE, (void*) & bcast, sizeof(bcast));
```

- 指定发送的目标IP为广播IP（如果没有指定`SO_BROADCASE`的话，给定的就是一个普通的IP了）
