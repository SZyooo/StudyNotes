# 套接字类型与协议设置

## 一、套接字协议 & 传输特性

### 1.1 协议(Protocal)

协议就是通信双方为了完成数据交换而定好的约定。

### 1.2 创建套接字

创建套接字的接口如下：

```
#include <sys/socket.h>
int socket(int domain, int type, int protocal);
```

这里将围绕这个接口来展开介绍协议。

### 1.3 协议族（Protocol Family）

`socket`函数第一个参数传递的是协议族。

协议族是对协议的分类。总体可分为以下几类

|名称|协议族|
|:-:|:-:|
|PF_INET|IPv4互联网协议族|
|PF_INET6|IPv6互联网协议族|
|PF_LOCAL|本地通信的UNIX协议族|
|PF_PACKET|底层套接字协议族|
|PF_IPX|IPX Novell协议族|

### 1.4 套接字类型（Type）

`socket`的第二个参数指定的是套接字的数据传输方式。下面介绍两中最经典的数据传输方式：

#### 1.4.1 面向连接的套接字（SOCK_STREAM）

这个传输方式可以理解为两个人通过传输带来进行数据传递，具有一下特点：

- 传输过程中数据不会消失
- 按顺序传递数据
- 传输的数据是不存在数据边界的
- 一对一的连接

收发数据的套接字内部有一个缓冲（buffer），类型是字节数组。这意味着通过套接字传输的数据可以缓存在该buffer，发送方多次发送的数据进入buffer后，接收方可以一次性拿出也可以分多次拿出。这便是数据不存在边界的原因。

> **[?]** 如果buffer溢出了，是否导致数据丢失？
> 答：不会。如果接收方的buffer溢出了，则发送方会停止发送数据，直到接受方buffer重新有空间。

#### 1.4.2 面向消息的套接字（SOCK_DGRAM）

这个传输方式可以理解为高速的快递，具有一下特征：

- 追求速度，但是不保证顺序：“快递员”快速扔下“包裹”，不在乎顺序
- 传输的数据不会保证正确性和完整性
- 传输的数据有边界：“快递员”扔出来的是一个个的盒子。意味着发送次数和接收次数一一对应
- 限制每次传输的数据大小

### 1.5 最终选择的协议

*协议族+数据传输方式* 在大部分时候已经可以决定采用什么协议了（第3个参数传0）。但是如果出现一个协议族中存在多个协议采用相同的传输方式的话，则我们需要传递第三个参数。

### 1.6 TCP和UDP

**IPv4协议族 + 面向连接**——IPPROTO_TCP

```C 
int tcp_socket = socket(PF_INET, SOCK_STREAM, IPPROTO_TCP);
```

**IPv4协议族 + 面向消息——IPPROTO_UDP

```C 
int udp_socket = socket(PF_INET, SOCK_DGRAM, IPPROTO_UDP);
```
