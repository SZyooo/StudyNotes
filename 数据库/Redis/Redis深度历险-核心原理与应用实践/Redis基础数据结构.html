基础与应用

一、Redis基础数据结构

Redis一共有5种基础数据结构：

  • 字符串（String）
  • 列表（List）
  • 集合（Set）
  • 有序集合（Sorted Set，ZSet）
  • 哈希（Hash）

1.1 string

字符串是Redis最基本的数据类型，内部表示是一个字符数组。Redis所有的数据结构都通过一个唯一的key字符串作为名称，只是key对应的value的结构不一样。

字符串内部是动态的，会预先分配冗余空间防止频繁扩容。在字符串小于1MB的时候，每次扩容都是x2的方式；大于1MB之后每次扩容都是增加1MB。

需要注意的是字符串的最大长度为512MB

1.1.1 键值对

相当于字典的key和value，支持简单的增删改查操作。

> set name codehole
OK
> get name
"codehole"
> exists name
(integer) 1
> del name
(integer) 1

1.1.2 批量键值对

可以对多个字符串进行批量读写操作，减少网络交互次数，提高效率。

> set name1 codehole
OK
> set name2 holycoder
OK
> mget name1 name2
1) "codehole"
2) "holycoder"
> mset name3 redis name4 database
OK
> mget name3 name4
1) "redis"
2) "database"
mset 表示的是 multi set，一次性设置多个键值对

1.1.3 过期和set命令扩展

可以对key设置过期时间，到时间会自动删除。

> set name codehole
OK
> get name
"codehole"
> expire name 5  # 设置过期时间为5秒
(integer) 1

还可以直接通过扩展的set命令设置过期时间：

> setex name 5 codehole  # 设置过期时间为5秒
OK

set 命令还支持只在key不存在时设置值：

> setnx name codehole  # 只在key不存在时设置值
(integer) 1

1.1.4 计数

如果value的值是一个整数，则可以对它进行原子性的增减操作。增减操作是有范围的，数据不能超过 signed long 最大值。 

> set age 30
OK
> incr age      # age加1
(integer) 31
> incrby age 5  # age加5
(integer) 36
> decr age      # age减1
(integer) 35

1.2 list 列表

Redis的列表是一个双向链表，可以在两端进行插入和删除操作。列表中的元素是有序的，可以通过索引访问。但是因为是链表，所以索引定位相对较慢。

快速列表 Redis底层存储的其实是快速列表（quicklist）。在元素比较少的时候，会使用一块连续的内存来存储，这个结构是ziplist（压缩列表）。当元素数量增加到一定程度时，会扩展一个新的ziplist来存储更多的元素。每个ziplist的大小默认是8KB，可以通过配置项 list-max-ziplist-size 进行调整。最终的结构是一个双向链表，每个节点存储一个ziplist。这样既能保证列表的高效存储，又能提供较快的访问速度。

1.3 hash 字典

Redis中的hash表示是一个键值对集合，采用的是桶式结构加链表的方式来存储，hash冲突之后冲突元素作为链表挂载在桶上。当hash表中的元素数量较少时，Redis会使用ziplist（压缩列表）来存储hash表，以节省内存空间。当元素数量增加到一定程度时，Redis会将ziplist转换为哈希表结构，以提高访问效率。每个hash表的大小默认是512KB，可以通过配置项 hash-max-ziplist-value 进行调整。

Redis中rehash采用的是渐进式rehash的方式，即在rehash过程中，旧表和新表会同时存在，并且每次对hash表进行访问时，都会进行一部分rehash操作，直到rehash完成为止。这种方式可以避免一次性rehash带来的性能问题，同时也保证了hash表的可用性。

1.4 set 集合

Redis中的set表示是一个无序的字符串集合，采用的是哈希表的方式来存储。set中的元素是唯一的，不允许重复。当set中的元素数量较少时，Redis会使用intset（整数集合）来存储set，以节省内存空间。当元素数量增加到一定程度时，Redis会将intset转换为哈希表结构，以提高访问效率。每个set的大小默认是512KB，可以通过配置项 set-max-intset-entries 进行调整。

1.5 zset 有序集合

Redis中的zset表示是一个有序的字符串集合，每个元素都会关联一个分数（score），zset中的元素是唯一的，不允许重复。当zset中的元素数量较少时，Redis会使用ziplist（压缩列表）来存储zset，以节省内存空间。当元素数量增加到一定程度时，Redis会将ziplist转换为跳表结构，以提高访问效率。每个zset的大小默认是128KB，可以通过配置项 zset-max-ziplist-entries 进行调整。

二、容器型数据结构的通用规则

Redis中的容器型数据结构（list、hash、set、zset）在设计上遵循了以下通用规则：

  1. create if not exists： 如果容器不存在，则自动创建一个
  2. delete if empty： 当容器中的元素被删除到空时，自动删除整个容器

三、过期时间

Redis所有的数据结构都可以设置过期时间，时间到了，Redis会自动删除相应的对象。
